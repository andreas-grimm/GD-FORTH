# Test 5.1: Simple IF/THEN Conditionals

## Overview

The **test-if-then.fs** file validates basic conditional execution using IF/THEN structures. Tests cover true conditions, false conditions, nested conditions, and stack effects of conditionals.

## Test Cases

1. **True condition execution**: Code executes when condition is true (-1)
2. **False condition execution**: Code skips when condition is false (0)
3. **Non-boolean conditions**: Any non-zero value treated as true
4. **Nested IF/THEN**: Multiple conditionals within conditionals
5. **Stack effects**: Conditionals with multiple stack items
6. **Arithmetic conditions**: Conditions generated by comparisons
7. **Empty branches**: IF/THEN with no code inside
8. **Deep nesting**: Multiple levels of IF/THEN nesting

## What Is Being Tested

- **Conditional execution**: IF/THEN only executes code when condition is true
- **Condition evaluation**: True = -1 (or any non-zero), False = 0
- **Stack consumption**: IF consumes the condition but not the data stack
- **Proper branching**: False conditions completely skip to THEN/ELSE
- **Nesting**: Multiple IF/THEN blocks can be nested correctly
- **Code after THEN**: Execution resumes after THEN regardless of branch taken
- **No premature termination**: If/Then doesn't exit outer constructs

## Structure of Test Cases

Each conditional test follows:

```forth
: <word-name>
   <condition> IF <true-branch> THEN <after-branch>
;
T{ <word-name> -> <expected-stack> }T
```

### Conditional Flow Diagram

```
┌─ True? ─┐
│         ├─► Execute true-branch ─┐
│         │                        │
│ IF cond │                   ┌────┘
│         │                   │
└─────────┴──► Skip if False ─┘
              │
              └──► Continue after THEN
```

## Code Documentation

### Basic IF/THEN with True

```forth
T{ : TEST1 TRUE IF 100 THEN ; TEST1 -> 100 }T
```

**Execution flow**:
1. Push TRUE (-1) to stack
2. IF consumes TRUE from stack
3. Condition is true, so execute code: 100
4. 100 is pushed to stack
5. THEN marks end of conditional
6. Return from word: stack has 100

**Expected stack**: 100

### Basic IF/THEN with False

```forth
T{ : TEST2 FALSE IF 100 THEN 200 ; TEST2 -> 200 }T
```

**Execution flow**:
1. Push FALSE (0) to stack
2. IF consumes FALSE from stack
3. Condition is false, so skip code (100)
4. Jump to THEN
5. Continue after THEN: push 200
6. Return from word: stack has 200

**Expected stack**: 200

**Key insight**: When condition is false, the entire IF/THEN block is skipped.

### Non-Boolean True Values

```forth
T{ : TEST3 1 IF 50 THEN ; TEST3 -> 50 }T
T{ : TEST4 0 IF 50 THEN 75 ; TEST4 -> 75 }T
T{ : TEST5 -1 IF 60 THEN ; TEST5 -> 60 }T
```

**Truthiness rules**:
- 0 is false
- Any non-zero value (positive or negative) is true
- -1 is true (even though it's negative)

This allows direct use of arithmetic results as conditions:
- `5 3 > IF` (5 > 3 produces -1, which is true)
- `0 IF` (0 produces false)

### Nested IF/THEN Structures

```forth
T{ : TEST6 TRUE IF FALSE IF 100 THEN 200 THEN ; TEST6 -> 200 }T
```

**Execution flow**:
1. Outer TRUE: IF executes
2. Push FALSE: inner IF consumes FALSE
3. FALSE condition: skip inner code (100)
4. Inner THEN: continue after inner IF to 200
5. Push 200
6. Outer THEN: end
7. Return: stack has 200

**Stack expected**: 200

```forth
T{ : TEST7 TRUE IF TRUE IF 300 THEN THEN ; TEST7 -> 300 }T
```

Both conditions true, so 300 executes.

### IF/THEN with Stack Operations

```forth
T{ : TEST8 5 TRUE IF 10 + THEN ; TEST8 -> 15 }T
```

**Execution**:
1. Push 5
2. Push TRUE
3. IF consumes TRUE (doesn't affect 5 on stack below)
4. Execute: 10 +
5. 5 + 10 = 15
6. THEN ends
7. Stack: 15

```forth
T{ : TEST9 5 FALSE IF 10 + THEN ; TEST9 -> 5 }T
```

1. Push 5
2. Push FALSE
3. IF consumes FALSE
4. Condition false: skip 10 +
5. THEN ends
6. Stack: 5 (unchanged)

### Arithmetic Conditions

```forth
T{ : TEST14 10 5 > IF 1 ELSE 0 THEN ; TEST14 -> 1 }T
T{ : TEST15 10 5 < IF 1 ELSE 0 THEN ; TEST15 -> 0 }T
```

Comparison operators (>, <, =, etc.) produce flags:
- 10 > 5 produces -1 (true)
- 10 < 5 produces 0 (false)

These flags are immediately consumed by IF.

### IF with Multiple Stack Items

```forth
T{ : TEST10 1 2 3 TRUE IF 4 THEN ; TEST10 -> 1 2 3 4 }T
T{ : TEST11 1 2 3 FALSE IF 4 THEN ; TEST11 -> 1 2 3 }T
```

IF only affects the condition. The rest of the stack is preserved:
- 1 2 3 TRUE: 1, 2, 3 remain below the condition
- IF consumes TRUE
- Data stack 1 2 3 is untouched
- Code executes or skips
- Result: 1 2 3 and either 4 (if true) or nothing (if false)

### Empty THEN Branch

```forth
T{ : TEST12 TRUE IF THEN 99 ; TEST12 -> 99 }T
T{ : TEST13 FALSE IF THEN 88 ; TEST13 -> 88 }T
```

An empty IF/THEN (no code between IF and THEN) is valid:
- It just skips an empty block or does nothing
- Code after THEN always executes

### Deep Nesting

```forth
T{ : TEST16 TRUE IF TRUE IF TRUE IF 999 THEN THEN THEN ; TEST16 -> 999 }T
```

Multiple levels of nesting work correctly. Each IF...THEN pair is matched properly by the parser.

### Failure Scenarios

**Condition Not Consumed:**
```
T{ TRUE IF 100 THEN -> 100 }T  (expects 100, got -1 100)
```
IF didn't consume the condition from the stack.

**Wrong Branch Executed:**
```
T{ FALSE IF 100 THEN 200 -> 200 }T  (expects 200, got 100)
```
IF always executes the true branch, regardless of condition.

**Nesting Error:**
```
T{ TRUE IF FALSE IF 100 THEN 200 THEN -> 200 }T  (expects 200, got error)
```
Parser doesn't correctly match nested IF...THEN pairs.

**Stack Corruption:**
```
T{ 1 2 3 TRUE IF 4 THEN -> 1 2 3 4 }T  (expects 1 2 3 4, got 1 2 4)
```
IF/THEN affected items below the condition on the stack.

## Notes

- **Condition consumption**: IF consumes the top stack item (the condition)
- **Stack isolation**: Data on the stack below the condition is never affected
- **Truthiness**: Any non-zero value is true; only 0 is false
- **Postfix syntax**: In Forth, condition comes before IF, not after
- **No ELSE**: Basic IF/THEN has no ELSE (use IF/ELSE/THEN for that)
- **Matching**: Parser ensures each IF is matched with exactly one THEN

## Execution Model

```
Stack before: [... data] [condition]
              ↓
IF consumes condition
              ↓
Stack after: [... data]
              ↓
Branch (true) or skip (false)
              ↓
Continue after THEN
```
